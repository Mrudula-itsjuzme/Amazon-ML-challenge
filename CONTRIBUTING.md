# Contributing

Thanks for your interest in contributing!

## Before opening a pull request
1. Open an issue describing the bug or proposed change, especially for substantial work.
2. Fork the repository and create a focused branch.
3. Follow existing conventions and keep changes small and reviewable.
4. Run applicable tests, checks, and documented reproduction steps before submitting.
5. Describe what changed, why, and how you validated it in the pull request.
6. Do not commit credentials, personal data, proprietary datasets, generated secrets, or large model artifacts.

For research results, provide dataset provenance, fixed seeds, evaluation commands, and limitations where relevant. Keep original source and third-party assets clearly distinguished.

## Licensing and attribution
By submitting a contribution, you agree that your original contribution may be distributed under this repository's existing license. Do not submit code or data you do not have rights to contribute. Respect third-party licenses, terms of service, and publication restrictions.

## Security reports
Do not file public issues containing working credentials or exploit details. Follow [SECURITY.md](SECURITY.md).
